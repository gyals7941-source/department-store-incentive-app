# 백화점 오프라인 인센티브 마감

엑셀 매크로(`26.09백화점_인센티브.xlsm`)로 하던 월마감을 웹앱으로 옮긴 것입니다.
파일 두 개를 올리면 차수 판정·인센티브 산정·배송 대조·이월 등록이 한 번에 끝나고,
이월명부와 마감이력은 서버에 남습니다.

## 매달 하는 일

1. **마감 실행** 탭에서 마감월을 고릅니다.
2. 이카운트확인(지점별 시트) 파일과 배송완료 원장을 올립니다.
3. 실행 요약을 확인합니다. 시트별 행수가 이카운트 화면과 같은지 꼭 보세요.
4. 수당안이 바뀌었으면 **설정 → 판매수당표**에서 그 달을 등록합니다.
5. 엑셀을 내려받아 영업팀에 공유하고, **마감 확정**을 눌러 이월명부에 반영합니다.

마감 확정을 누르면 그 달에 지급되는 이월 건은 자동으로 `지급완료`가 되고 지급월이 적힙니다.
실제 지급이 달라졌을 때만 **이월명부** 탭에서 직접 고칩니다.

## 실행

```bash
streamlit run app.py
```

접속 정보가 없으면 `data/` 폴더를 쓰고, 있으면 데이터 저장소를 씁니다.
지금 어느 쪽인지는 설정 탭 아래에 적힙니다.

## 클라우드에 올리기

노트북과 회사 컴퓨터 양쪽에서 쓰려면 두 조각이 필요합니다.

| | 맡는 일 |
|---|---|
| GitHub 저장소 2개 | 코드 하나, 데이터 하나. **반드시 따로 둡니다.** |
| Streamlit Cloud | 앱을 실제로 띄우는 곳. 코드 저장소를 바라봅니다. |

데이터를 코드 저장소에 같이 두면 **저장할 때마다 앱이 다시 배포됩니다.**
그래서 데이터 저장소를 따로 만듭니다.

저장은 곧 커밋이라 이력이 영구히 남습니다. "9월 마감 직후 명부가 어땠는지"를
GitHub 에서 그대로 펼쳐볼 수 있고, 따로 백업을 돌릴 필요가 없습니다.

### 1. 데이터 저장소

**비공개(private)** 로 만듭니다. 여기에만 실제 금액이 들어갑니다.

```bash
gh repo create <이름>-data --private
```

### 2. 토큰

GitHub → Settings → Developer settings → Personal access tokens →
**Fine-grained tokens** → Generate new token.

| 칸 | 값 |
|---|---|
| Repository access | Only select repositories → **데이터 저장소 하나만** |
| Permissions | Repository permissions → **Contents: Read and write** |
| Expiration | 1년 (최대) |

Contents 하나면 충분합니다. 다른 권한은 주지 마세요.

만들면 `github_pat_...` 로 시작하는 문자열이 **한 번만** 보입니다. 복사해 두세요.

### 3. 지금 데이터 옮기기

`.streamlit/secrets.toml.example` 을 `secrets.toml` 로 복사해 값을 채운 뒤,

```bash
python push_to_cloud.py
```

무엇이 올라갈지 먼저 보여줍니다. 맞으면 `--실행` 을 붙여 다시 돌립니다.

### 4. 코드 저장소

**비공개** 로 만듭니다. 공개하면 계산 로직과 거래처 이름이 노출됩니다.

```bash
git init && git add . && git commit -m "백화점 인센티브 마감"
gh repo create <이름> --private --source=. --push
```

`git status` 로 `data/` 와 `secrets.toml` 이 안 보이는지 확인하고 올리세요.

### 5. Streamlit Cloud

1. share.streamlit.io 에서 GitHub 계정으로 들어가 **코드 저장소**를 연결합니다.
2. 메인 파일은 `app.py`.
3. Advanced settings → Secrets 에 `secrets.toml` 내용을 그대로 붙여넣습니다.
4. 앱 설정 → Sharing 에서 볼 범위를 정합니다. 두 가지 중 하나입니다.

   - **Only specific people** — 초대한 메일로 구글 로그인한 사람만. 더 안전합니다.
   - **Anyone with the link** + 아래 핀번호 — 로그인 없이 핀만으로 들어갑니다.
     편한 대신 **주소와 핀이 함께 새면 누구나 열립니다.**

### 핀번호

`secrets.toml` 의 `[app] pin` 에 적습니다. 비워 두면 묻지 않습니다(사내 PC·로컬용).

주소가 공개돼 있으므로 **숫자 4자리는 쓰지 마세요.** 글자를 섞어 길게 쓸수록
안전합니다. 5번 틀리면 1분, 그 뒤로는 틀릴 때마다 잠기는 시간이 늘어납니다
(최대 10분). 한 번 통과한 브라우저는 8시간 동안 다시 묻지 않습니다.
설정 탭의 ‘나가기’를 누르면 바로 다시 묻습니다.

바꾸려면 Streamlit Cloud → 앱 → Settings → Secrets 에서 `pin` 만 고치면 됩니다.

### 토큰 갱신 (1년에 한 번)

만료 30일 전부터 앱 위쪽에 경고가 뜹니다. GitHub 도 1주일 전에 메일을 보냅니다.

1. 위 2번과 똑같이 새 토큰을 만듭니다(기존 토큰 화면의 Regenerate 도 됩니다).
2. Streamlit Cloud → 앱 → Settings → Secrets 에서 `token` 과 `expires` 를 고칩니다.
3. 저장하면 앱이 알아서 다시 뜹니다.

만료되면 계산은 되는데 **저장만 안 됩니다.** 당황하지 말고 토큰만 갈아 끼우면
그동안의 데이터는 그대로 있습니다.

## 저장되는 것

| 파일 | 내용 |
|---|---|
| `이월명부.csv` | 살아 있는 명부. 월마다 새로 만들지 않고 계속 갱신됩니다. |
| `마감이력.json` | 확정한 마감의 요약과 지점별 결과. |
| `수당표.json` | 적용월별 판매수당표. 그 달 표가 없으면 직전 달을 이어받습니다. |
| `거래처.json` | 지점 목록, 다른 표기(별칭), 목표금액. |
| 마감본 | 확정 시점에 내보낸 엑셀 사본. |

로컬이면 `data/` 폴더, 클라우드면 비공개 데이터 저장소의 같은 이름 파일입니다.
로컬은 덮어쓰기 전 사본을 20개까지 남기고, 클라우드는 커밋 이력이 그 역할을 합니다.

쓰기 전에 자동으로 백업본을 만들고 최근 20개를 남깁니다.

## 구조

```
app.py              화면 (Streamlit)
ui.py               화면 껍데기 — 색·카드·헤더
core/engine.py      계산 엔진 (엑셀 수식을 그대로 옮긴 것)
core/io_in.py       업로드 파일 읽기
core/rates.py       월별 수당표
core/stores.py      거래처 마스터
core/storage.py     이월명부·마감이력
core/backend.py     저장소 뒤쪽 — 로컬 파일 또는 GitHub 데이터 저장소
core/excel_out.py   엑셀 내보내기
core/xlsm_reader.py 기존 .xlsm 읽기 (검증·이관용)
validate.py         기존 엑셀과 1원 단위 대조
seed.py             최초 1회 — 기존 엑셀에서 이월명부·이력 이관
push_to_cloud.py    최초 1회 — 로컬 data/ 를 데이터 저장소로
```

계산 로직은 `core/` 에만 있습니다. 화면은 숫자를 만들지 않습니다.

## 검증

```bash
python validate.py "백화점_인센티브_26.09_최종.xlsx"
```

기존 엑셀의 `영업팀공유` 시트와 엔진 결과를 지점별로 대조합니다.
2026년 8·9월 및 9월 최종본에서 전 항목 일치를 확인했습니다
(7월은 템플릿 세대가 달라 대조 대상에서 제외).

## 알아둘 것

- **수당표는 달마다 바뀝니다.** 7·8월은 같았고 9월에 크게 개정됐습니다
  (제외된 품목, 온라인 전용 품목 추가, 일부 품목 단가 조정).
  월별로 보관하므로 지난달을 다시 열어도 그때 기준 그대로 재현됩니다.
- **온라인/오프라인 구분은 적요의 주문번호 모양으로 합니다.** 날짜 8자리
  (`20YYMMDD`) 뒤에 영숫자가 붙고 하이픈이 없으면 온라인몰 건입니다.
  꼬리는 숫자일 수도(`202610036231684`) 영문이 섞일 수도(`20261001D1B9CD`)
  있습니다. 하이픈이 들어간 특판 번호(`20261008-2차오프-004`), `현장판매`·
  `매장지급` 같은 메모, 사은품 줄의 품목명, 빈칸은 모두 오프라인입니다.
  품목명의 `[[온]]`·`[[오프]]` 태그는 쓰지 않습니다.
- 이 구분은 수당안에 **「온라인만 운영」으로 적힌 품목**에만 영향을 줍니다.
  그 품목은 오프라인으로 팔리면 수당이 0원입니다. 차수 판정의 정상가 합계에는
  온·오프라인이 모두 들어갑니다.
- **같은 매장이 이카운트에 다른 이름으로 찍히는 경우가 있습니다.**
  설정의 ‘다른 표기’로 묶어두면 자동 합산됩니다. 어떤 매장이 그런지는
  설정 → 거래처에서 확인하세요.
- **수당표에 없는 품목코드는 수당 0원입니다.** 수당 대상이 아닌 품목은
  단가 0으로 등록해두면 매달 경고가 뜨지 않습니다.
- **화면 글꼴(Pretendard)은 인터넷에서 받아옵니다.** 주소는 `ui.py` 의 `FONT_CSS`
  한 줄입니다. 사내 서버가 외부망에 못 나가면 글꼴만 기본값으로 떨어지고
  숫자·계산에는 영향이 없습니다. 그 경우 글꼴 파일을 프로젝트 안에 두고
  그 줄을 로컬 경로로 바꾸면 됩니다.
- **배송원장 열 순서는 바뀝니다.** 2026년 중 소비자명이 4열에서 13열로 옮겨가며
  그 사이가 한 칸씩 당겨졌습니다. 열 번호가 아니라 머리글 이름으로 찾으므로
  순서가 또 바뀌어도 됩니다. 다만 머리글에 `구분` 과 `주문코드` 는 있어야 합니다.
- 이카운트 시트 중간에 빈 행이 있으면 `Ctrl+Shift+↓` 복사가 거기서 멈춥니다.
  실행 요약의 시트별 행수를 꼭 확인하세요. 2026년 9월에 이 사고로
  한 지점의 2건이 마감에서 빠진 적이 있습니다.

## 환경변수 (점검용)

`DEMO_SALES`, `DEMO_DELIV` 에 파일 경로를 넣어두면 업로드 없이 그 파일로
화면을 띄워볼 수 있습니다. 평소에는 설정하지 않습니다.
